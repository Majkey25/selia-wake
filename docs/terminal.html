No desktop required.

The standalone CLI is one executable. A spare laptop, Linux server or Raspberry Pi can be The Waker. It needs neither Flutter nor GTK. Keep it powered, awake and on the target's LAN.

Pick the right package

SystemCLI archive
Windows x64selia-wake-cli-windows-x64.zip
Linux x64selia-wake-cli-linux-x64.tar.gz
Linux ARM64selia-wake-cli-linux-arm64.tar.gz
Linux ARMv7selia-wake-cli-linux-armv7.tar.gz

For Raspberry Pi, match the installed OS architecture, not just the board name. A 64-bit OS needs ARM64. A compatible 32-bit ARMv7 OS needs ARMv7. Pi 1 and first-generation Pi Zero use ARMv6 and cannot use the ARMv7 package. Cross-built ARM packages still need testing on your board.

Download from GitHub Releases, verify the archive against that release's SHA256SUMS, and extract it. Linux example:

tar -xzf selia-wake-cli-linux-arm64.tar.gz
chmod 755 ./seliawake
./seliawake help

Run it from its own folder as your normal user. On Windows, extract the ZIP and use .\seliawake.exe. It does not install a service, change the firewall or create automatic startup.

Configure The Waker

Install and connect Tailscale separately. Use the Waker's assigned Tailscale IPv4 and physical LAN IPv4, plus the target's MAC. Replace these examples:

./seliawake init-waker --tailnet-ip 100.101.102.103 --lan-ip 192.168.1.20 --mac 02:11:22:33:44:55 --broadcast 192.168.1.255 --name Home
./seliawake status
./seliawake send-local
./seliawake export-pairing --show-secret
./seliawake serve --allow-tailnet

Export reveals a private pairing link. Transfer it only to trusted devices. serve listens on the configured Tailscale IPv4 at TCP 45879 until Ctrl+C. Stop any GUI relay on that device first. Keep this terminal running. Restrict access using tailnet and firewall rules.

Wake from another computer

./seliawake pair --stdin

Paste the secret pairing URI, then end input with Ctrl+D on Linux or Ctrl+Z followed by Enter on Windows. Input can be echoed by your terminal. Do not include the secret in a command argument, shell history or environment variable.

./seliawake status
./seliawake wake

A GUI User can also import a CLI Waker's link. A CLI User can import a GUI Waker's link. “Packet sent” does not confirm target startup. status shows local configuration, not remote availability.

Settings and removal

Use --config-dir DIRECTORY before a command to keep separate configurations. Existing files are never overwritten. To change the target, role or key, stop the old relay and create a new configuration directory. Re-pair when the key or address changes. GUI and CLI settings are separate.

The secret is plaintext in config.json. Linux creates owner-only permissions. Windows uses a protected access list. Keep this file on a trusted local filesystem, outside shared or synced folders. status displays the config directory without the key. Stop the relay and remove that directory yourself to reset it. See the complete CLI reference.

ESP32 and other Arduino boards

ESP32 companion firmware is a separate experimental port. It uses the Arduino ESP32 core, USB serial configuration and local Wi-Fi. It requires an always-on Tailscale gateway that forwards the tailnet listener to the ESP32. The board does not run Tailscale itself. The signed request format remains the same.

Read the ESP32 build, configuration and gateway guide before flashing. No ESP32 hardware test is claimed. Classic Arduino Uno boards lack the networking and resources required by this firmware. Other boards need their own implementation; there is no universal installer for every microcontroller.

When wake fails

Check the target adapter and firmware setup. Keep The Waker on the same broadcast network as the target. Check its physical LAN source address, current Tailscale connection, automatic clock synchronization, sleep policy and client isolation. The protocol rejects stale requests. If the Waker's LAN address changes, update configuration before restarting it.
