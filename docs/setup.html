Connect and wake

You need a target computer, an awake Waker at home, and a remote User device. Install Selia Wake on the User and Waker. On Windows or Linux, the target computer can also run Selia Wake in The Sleeper role to configure its network adapter and export setup details.

1. Prepare the target

Enable wake in its firmware and connected adapter's driver. Use the MAC address of the adapter that stays connected during sleep. Ethernet requires an attached cable. First test wake from sleep. Shutdown wake depends on the hardware, firmware and power state.

On Windows and Linux desktop, you can switch Selia Wake to The Sleeper role in Settings. Sleeper inspects the operating system's sleep states and active physical network adapters, and enables OS Wake-on-LAN settings for the selected adapter (via powercfg on Windows or ethtool on Linux). These actions adjust operating system and driver configuration only. They cannot inspect, verify, or enable BIOS or UEFI firmware settings (such as APM configuration, PCIe/WoWLAN wake, and ACPI sleep states). You must still verify and enable Wake-on-LAN in the computer's firmware setup. Software configuration alone does not prove that hardware wake will succeed.

On Linux, Sleeper uses ethtool to query and enable Wake-on-LAN. Because ethtool changes apply to the running kernel and may reset across reboots, persistent configuration may require NetworkManager settings (such as nmcli connection modify <conn> 802-3-ethernet.wake-on-lan magic). Selia Wake does not install automatic startup scripts, system daemons, or background services.

Click Export target / QR on The Sleeper to display a QR code or copy the target setup link. The setup link contains network details (computer name, MAC, broadcast, connection type, and optional target IP for availability checks), but no secret key. Clipboard writing happens only when you explicitly click Copy link.

Wireless wake on Windows

Your Wi-Fi adapter, driver and firmware must support WoWLAN. In Device Manager, open the Wi-Fi adapter. Enable Wake on Magic Packet under Advanced. Under Power Management, allow the device to wake the computer if the driver exposes that setting.

List programmable adapters and devices that report S3 wake support:

powercfg /devicequery wake_programmable
powercfg /devicequery wake_from_S3_supported

Open Terminal as administrator. Replace ADAPTER NAME with the exact device name from the output:

powercfg /deviceenablewake "ADAPTER NAME"

Check that the Wi-Fi adapter appears in the enabled list:

powercfg /devicequery wake_armed

In Selia Wake, select Wi-Fi (WoWLAN) as the target connection and enter the target's Wi-Fi MAC. These commands show capabilities and configuration. Only an actual sleep-and-wake test proves that the complete path works. Selia Wake cannot add missing hardware support.

2. Connect Tailscale

Install Tailscale separately on the Waker and User. Sign both into your tailnet and connect them. Tailnet access rules must allow the User to reach the Waker on TCP 45879. No public router forwarding is needed.

The Waker must also stay connected to the target's physical LAN. Guest Wi-Fi, client isolation and separate VLANs can block the wake broadcast. If the Waker uses an exit node, its VPN settings must allow local LAN traffic.

3. Configure The Waker

Choose The Waker in Settings on the device at home. Enter the target name, MAC and connection type, or use Paste Sleeper setup or Scan Sleeper QR on Android. Valid settings save automatically. Invalid fields prevent saving.

Detect network fills empty addresses; check the result. Enter the Waker's Tailscale IPv4, such as 100.x.x.x, and the local broadcast address. On desktop, also select the physical LAN IPv4 source. Return and start The Waker.

Send local test packet applies valid configuration and sends a magic packet on the local LAN without a remote request. The Waker must stay awake.

A Windows or Linux laptop works in the same role as a phone. Keep it plugged in and awake. Check lid-close and sleep settings yourself. The GUI must stay open; for a headless machine use the CLI.

4. Pair the User

Open Pairing link / QR in the Waker's Settings. On the other Android, select User and Scan QR code, or paste the copied link. Windows and Linux import the link. Valid pairing saves automatically. Check the displayed name and address.

Both forms carry the secret. Keep them private. Import inside Selia Wake; do not publish the code or paste it into a search engine. Clipboard access occurs only after explicit Copy or Paste actions. Forget pairing removes this installation's User connection automatically. It does not revoke other copies of a Waker key.

Revert changes restores settings from when you opened the page. Reset defaults clears connection settings, restores default appearance and generates a new Waker key. It stops a running Waker. Old clients need new pairing. Revert can undo the reset while the page stays open, including restoring the old key. It does not start an inactive Waker or change OS wake settings.

5. Test from sleep

Save work on the target and put it to sleep. Leave The Waker running on the home LAN, with Tailscale connected on both devices. Press Wake from the User. “Packet sent” confirms transmission, not target startup. On Windows, check the last wake source after the test:

powercfg /lastwake

Check computer availability

Under Settings, you can optionally configure the target computer's private LAN or Tailscale IPv4 address and a TCP service port. Standard services include Windows Remote Desktop (RDP port 3389) or SSH (port 22). To check availability remotely over Tailscale, install and sign into Tailscale on the target computer as well, using the target PC's own Tailscale IPv4 address (not the Waker's).

When you press Wake on the User device, Selia Wake checks the target TCP port and retries for up to 60 seconds while kept in the foreground. A successful connection confirms that the TCP service is reachable over the network. It does not verify operating system boot completion, host identity, or user login. If the check times out or fails, the result is inconclusive because a host firewall, blocked port, or stopped service produces the exact same result as a sleeping computer.

USB and background operation

USB Ethernet requires a wake-capable adapter that remains powered in the sleep state you test. A normal phone charging cable cannot wake the PC through Selia Wake. The app does not turn a phone into a USB keyboard.

On Android, allow background operation for both Selia Wake and Tailscale. The Waker shows a persistent notification and Stop action. Manufacturer battery restrictions can still stop it. Use a wall charger. Start the Waker again after restarting the device.

Desktop firewalls should allow TCP 45879 only from intended tailnet peers. The app does not configure firewalls or change system sleep policies. The Sleeper changes only the selected adapter's wake settings when you explicitly choose Enable wake.
